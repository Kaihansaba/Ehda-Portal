# Project Backlogs

## Project: Ehda Portal — Online Blood Donation Platform

### 1. Overview

This folder contains the product and sprint backlog documents for Ehda Portal, an online blood donation platform developed as part of the Software Engineering course using the Scrum framework.

The backlogs organize the project's requirements, prioritize development tasks, and define the work planned for each sprint. They help the team track progress, assign responsibilities, and ensure that development activities remain aligned with the project objectives.

### 2. Documents Included

#### 2.1 Product Backlog

The Product Backlog contains the prioritized list of features, requirements, improvements, and other work needed to develop Ehda Portal. It includes user stories related to account management, donor profiles, donor search, location privacy, blood requests, notifications, messaging, donation history, and administrative functions.

Each backlog item should have a unique identifier, description, priority, story points, status, sprint assignment when applicable, responsible team member, and acceptance criteria.

#### 2.2 Sprint Backlog

The Sprint Backlog describes the work selected for all particular sprints and explains how the team plans to achieve the sprint goal. It connects the selected product backlog items with the development tasks required to complete them.

The sprint backlog should be updated as work progresses and should reflect the team's actual progress, assignments, and remaining work.

#### 2.3 Sprint 1 Backlog — Foundation

This document records the work planned for the first sprint, focusing on establishing the project's foundation. Depending on the agreed requirements, this may include project setup, initial documentation, database planning, account-related functionality, and other foundational tasks.

It records the sprint goal, selected backlog items, assigned responsibilities, acceptance criteria, and actual completion status.

#### 2.4 Sprint 2 Backlog — Donor Search and Location

This document records the work selected for the second sprint, focusing on donor search and location-related functionality. Planned work may include searching by blood type and location, displaying approximate donor locations, and protecting sensitive location information.

It tracks the selected user stories, development tasks, responsible team members, dependencies, and progress toward the sprint goal.

#### 2.5 Sprint 3 Backlog — Blood Requests and Communication

This document records the work planned for the third sprint, focusing on blood request management and communication between users. Planned work may include sending requests, accepting or declining requests, notifications, and messaging after request acceptance.

The backlog should document the relevant user stories, implementation tasks, acceptance criteria, and actual progress.

#### 2.6 Sprint 4 Backlog — Administration, Testing, and Finalization

This document records the work planned for the fourth sprint, focusing on administrative functions, testing, integration, bug fixing, documentation updates, and final product preparation, as applicable to the agreed project scope.

It helps the team track remaining work, verify completed functionality, document test results, and prepare the final demonstration and submission.

### 3. Purpose of the Backlogs

The backlogs help the team to:

- Organize and prioritize project requirements.
- Break user stories into manageable development tasks.
- Set clear goals for each sprint.
- Assign responsibilities and identify dependencies.
- Track planned, ongoing, completed, and incomplete work.
- Verify progress against acceptance criteria.
- Support sprint planning, daily Scrum meetings, sprint reviews, and retrospectives.
