# Sprint 3 — Request Responses and Communication

## Sprint Information

- **Project:** Ehda Portal — Online Blood Donation Platform
- **Sprint Duration:** 5 days
- **Start Date:** 19-Oct-2026
- **End Date:** 23-Oct-2026
- **Sprint Manager:** Madina Pasun, Madina Afshar

## 1. Sprint Description

Sprint 3 focuses on completing the blood-request workflow. Donors should be able to receive notifications and accept or decline requests, while blood seekers should be able to view the responses. Messaging will become available after a request is accepted. This sprint also includes integration testing, defect retesting, and preparation of the Software Requirements Specification (SRS), use case diagram, and sequence diagram.

## 2. Sprint Objectives

- Notify donors when they receive blood requests.
- Allow donors to accept or decline requests.
- Display request statuses and responses to blood seekers.
- Enable communication after a request has been accepted.
- Validate requests and handle communication errors.
- Integrate the developed features and retest defects.
- Document functional and non-functional requirements.
- Prepare use case and sequence diagrams.
